## 人工更新流程

使用 Node 24、系統 `curl` 及已安裝的專案依賴。更新腳本由維護者執行，訪客瀏覽器使用編入版本的快照；沒有排程、自動發布或即時資料同步。

```bash
node scripts/refresh-insurance.mjs --check
node scripts/refresh-insurance.mjs --write
node scripts/refresh-laws.mjs
node scripts/refresh-calendar.mjs
npx oxfmt src/data/insurance.ts src/data/laws.ts src/data/calendar.ts
npm test
npm run lint
npm run format:check
npm run build:company
git diff --check
```

- 勞健保 `--check` 只重新下載與核對已登錄版本；`--write` 在雜湊、欄位、日期與級數檢查通過後重建快照。來源版本變動須先檢查官方公告並調整版本登錄，不默默覆蓋成未核對新版。
- 法規腳本逐一核對名稱與日期、整編截止日及三站公告格式；全部成功後才寫入 `src/data/laws.ts`。保留來源日期與生效提示，不能以公告日推論施行日。
- 日曆腳本核對全年日期連續性、星期、備註與已知年度總數，成功後才寫入 `src/data/calendar.ts`；新增年度須取得並登錄官方來源，不能平移農曆事件。
- 來源取得或內容驗證失敗時保留原快照。成功後仍須人工檢查 `git diff`、讀回畫面日期與來源，完成測試及建置後才納入發布；更新命令本身不代表已部署。

## 驗收條件

1. 十工具具可操作的輸入、驗證、結果及必要的複製／匯出；舊發票、查詢與 PNG 操作維持可用。分攤合計等於原總額，日期拒絕不存在的日期。
2. 官方資料可追溯來源與核對／適用日期；公告、修正與生效不得混為一談；政府辦公日曆不得直接宣稱所有勞工都適用。不存在或未核對的年度不能自行推算為官方資料。
3. 執行 Node 24 測試、lint、格式與公司子路徑建置，真實瀏覽器檢查桌面／手機主要流程，並讀回實際文件與 ICS 下載。最後結果與尚未驗證部分寫入[驗證紀錄](VERIFICATION.md)。 發布十工具版本後另行核對 `/invoice/` 靜態資源及主要操作；保留回復資訊，不沿用三工具舊版的成功宣告。
