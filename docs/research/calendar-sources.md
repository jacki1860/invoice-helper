# 臺灣 2026／2027 行事曆資料來源與驗證

研究與實抓日期：2026-09-30。資料提供機關：行政院人事行政總處（DGPA）。

## 結論

採人事行政總處「一般 CSV」作全年日期來源，保留原始備註，再產生前端快照與 ICS。2026（民國 115）、2027（民國 116）都已有官方公告，無須推算農曆。一般 CSV 各含 365 日；Google 版只含放假事件，而且夾有空白資料列，不適合作為完整月曆的主來源。

工具呈現「國定假日原日期」「政府行政機關補假」「一般週末」三類。全年 ICS 只納入前兩類，共 22／24 筆，不把普通週末包裝成國定假日。

## 適用邊界與分類

政府行政機關日曆適用公務人員；特殊機關、學校、軍事機關可能由主管機關調移。一般政府機關的週六／週日補假規則不能直接當作所有勞工的排班表。勞動部另明定，勞工國定假日碰上原約定例假或休息日，補假日期由勞雇協商；把國定假日與工作日對調，需勞工個人同意。

因此工具列出法定節日原日期及政府補假參考，不判斷個別雇用關係的出勤、加班費或應補假日。原住民族歲時祭儀、具投票權且原為工作日等有個別適用條件的假日，也不在這兩份一般日曆快照內。

實作分類依已驗證資料：非空節日名稱＝原日期；「補假」＝政府補假；無備註且代碼 2＝一般週末；代碼 0＝政府上班日。refresh script 對目前來源的已知備註、日期連續性、星期與年度總數採明確檢查；未來出現新備註或資料格式時會停止並要求人工檢視，避免默默錯誤分類。

## ICS 輸出規則

依 [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545) 的 3.1、3.2.19、3.3.11、3.6.1、3.8.4.7：

- 使用 `VERSION:2.0`、`PRODID`，每筆 `VEVENT` 提供穩定 `UID` 與 UTC `DTSTAMP`。
- 全天日期用 `DTSTART;VALUE=DATE:YYYYMMDD`；`DTEND` 是不含在事件內的次日。2027-12-31 事件結尾必須為 `20280101`。
- `DATE` 不加 `TZID`，不以午夜時間取代全天日期，避免跨時區轉日。
- UTF-8、CRLF；每個實體行不超過 75 octets，續行以空格開頭，不切斷 Unicode 字元。
- `SUMMARY`、`DESCRIPTION` 內反斜線、逗號、分號、換行要做 TEXT escaping。
- 不使用每年重複規則推算農曆；逐筆輸出官方公布的日期。

產品選擇：檔名包含年份，`TRANSP:TRANSPARENT` 不佔忙碌時間；事件描述保留政府日曆來源與民間補假適用說明。相同事件 UID 維持一致；各日曆產品重複匯入時是否去重，仍須以實際客戶端驗證。

## 更新與驗證方法

已實作 `scripts/refresh-calendar.mjs`，以系統 `curl` 取得上述固定官方資源；需 Node 24+、curl 與專案既有的 oxfmt，沒有新套件、排程或背景請求。所有年度完成驗證後才寫入 `src/data/calendar.ts`，保留取得日期、來源網址與雜湊。失敗時不覆寫現有快照。

```sh
npm exec --yes --package=node@24 -- node scripts/refresh-calendar.mjs
npm exec --yes --package=node@24 -- node --test tests/calendar.test.ts
```

發布前檢查 snapshot diff。新增 2028 或後續年份時，先等官方公告，再把官方 CSV 連結與已確認總數加入 script，擴充測試；不能只用公式把 2027 農曆事件平移。

2026-09-30 驗證紀錄：

- Node 24.21.0：6 個行事曆測試通過，涵蓋全年資料、已知節日／補假、24 個月的星期欄位、ICS 全年事件、跨年 DTEND、Unicode escaping／folding 與穩定 UID。
- refresh script 連續執行兩次，輸出快照位元組一致；針對變更檔的 lint 與格式檢查通過。
- Chrome 本機預覽：年份與月份切換、2026-12 → 2027-01、兩端導覽停用、無事件月份、本月返回已操作確認；完整桌面月曆與來源說明已目視。手機版由主代理另行整合驗證。
- 真正點擊下載取得 `taiwan-holidays-2026.ics`（9,297 bytes、22 筆）及 `taiwan-holidays-2027.ics`（10,139 bytes、24 筆），對磁碟檔案重新解析確認 CRLF、UTF-8、最多 75 bytes／行與全年日期邊界；2027-12-31 的結尾確為 2028-01-01。
